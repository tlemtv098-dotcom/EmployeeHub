# Signup / Login Registration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** เพิ่มระบบสมัครสมาชิกให้ใครก็สมัครเองได้ด้วย username/email/password แล้วไปหน้า login

**Estimated tasks:** 3 | **Estimated time:** ~25 min | **Touches:** employees/forms, employees/views, employees/urls, templates/registration

## Current Problem / Current Solution

- มีแค่ `login/` + `logout/` ใช้ `auth_views.LoginView` กับ `templates/registration/login.html` ไม่มีหน้าสมัคร
- User ต้องสร้างผ่าน `createsuperuser` หรือ `build.sh` admin/1234 เท่านั้น
- ไม่มี `SignupForm` / `signup` view / `signup.html` / ลิงก์ไปสมัคร

## Proposed Approach

- เพิ่ม `SignupForm` ต่อยอด `UserCreationForm` เพิ่ม `email` (required, validate unique) + `username`/`password1`/`password2` มาตรฐาน
- เพิ่ม `signup` view (GET โชว์ฟอร์ม, POST validate -> `form.save()` -> `messages.success` -> redirect `login`) ตาม Q11=B ไม่ auto-login
- เพิ่ม `templates/registration/signup.html` สไตล์เดียวกับ `login.html` (ใช้ `app.css` + `login-card`) และเพิ่มลิงก์ `สมัครสมาชิก` ใน `login.html` <-> `เข้าสู่ระบบ` ใน `signup.html`
- เพิ่ม `path("signup/", views.signup, name="signup")` ใน `employees/urls.py`

## Side by Side

| Scenario | Before | After |
| -------- | ------ | ----- |
| คนทั่วไปอยากใช้ | ต้องขอแอดมินสร้างให้ | กด สมัครสมาชิก กรอก username/email/password -> สมัครได้เอง |
| หลังสมัคร | - | เด้งไป `/login/` พร้อมข้อความ "สมัครสำเร็จ กรุณาเข้าสู่ระบบ" (Q11=B) |
| login page | ไม่มีทางไปสมัคร | มีลิงก์ "ยังไม่มีบัญชี? สมัครสมาชิก" |

## Assumptions & Risks

- **Assumed:** ใช้ `django.contrib.auth.models.User` เดิม ไม่สร้าง Custom User (Q10=A)
- **Assumed:** เปิดให้ทุกคนสมัครได้ ไม่ต้องแอดมินอนุมัติ (Q9=A) -> เสี่ยงสแปมแต่รับได้สำหรับทดสอบ
- **Assumed:** ไม่ต้องยืนยันอีเมล (Q11=B ไม่ใช่ C)
- **Risk:** `email` ซ้ำไม่ได้ validate อาจสมัครซ้ำ -> ต้องใส่ `clean_email` unique check
- **Risk:** `AUTH_PASSWORD_VALIDATORS = []` ว่างอยู่ รหัสอ่อนผ่านได้ -> รับได้ตามโปรเจกต์เดิม

## Impact

- คนทั่วไปสมัครเองได้ ลดภาระแอดมิน
- โฟลว์สอดคล้อง login เดิม ไม่กระทบ `login_required` ทั้งระบบ
- ไม่ต้อง migrate เพิ่ม (ใช้ User เดิม)

from django.contrib.auth.forms import UserCreationForm
from django.contrib.auth.models import User

class SignupForm(UserCreationForm):
    email = forms.EmailField(required=True, label="อีเมล", widget=forms.EmailInput(attrs={"placeholder":"email@example.com"}))
    class Meta:
        model = User
        fields = ("username","email")
        widgets = {"username": forms.TextInput(attrs={"placeholder":"ชื่อผู้ใช้"})}
    def clean_email(self):
        email = self.cleaned_data["email"]
        if User.objects.filter(email__iexact=email).exists():
            raise forms.ValidationError("อีเมลนี้ถูกใช้งานแล้ว")
        return email
```

from django.shortcuts import render, redirect
from .forms import SignupForm
from django.contrib import messages

def signup(request):
    if request.user.is_authenticated:
        return redirect("dashboard")
    if request.method == "POST":
        form = SignupForm(request.POST)
        if form.is_valid():
            form.save()
            messages.success(request, "สมัครสมาชิกสำเร็จ กรุณาเข้าสู่ระบบ")
            return redirect("login")
    else:
        form = SignupForm()
    return render(request, "registration/signup.html", {"form": form})
```
